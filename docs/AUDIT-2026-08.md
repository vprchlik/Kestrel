# AUDIT 2026-08 — pre-M4 whole-tree audit

Audited at `main` = `4660fab` (post-M3, post zero-warnings cleanup), before
any M4 code. Method: every source file, the linker script, and every script
the gates run, read end to end; findings only, no fixes in the audit pass.
Trigger: the FREEZE phase stamp was found to mislabel its dominant work
while sixteen gates were green and the build had zero warnings — so the
same skepticism was applied to everything M4 inherits.

Two findings were **pre-registered predictions** T4.2 had to confirm or
refute (D-0057): finding 10's cost inventory of the measured path, and
finding 12's prediction that `first_rx` / net-init-tail deltas show ~10 ms
tick-quantized variance across trials. If the data disagreed with either,
one of them was wrong and the disagreement is itself a result. The M4
report may cite this file as the before-the-fact record.

**T4.2 outcomes — both go in the report.** Finding 10 was checked
item-by-item (D-0057). The three wrong-class items (`task_init`,
`virtq_init`, `stvec`) share a direction: predicted µs, measured sub-ms.
That is a systematic bias in the audit's cost estimates, and an
observation about pre-registration itself. Finding 12 is **refuted**:
release+fast-boot `first_rx` was 0.60 ms, no tick quantization. Cause:
D-0056.3 (T4.0b) had already removed `wfi` from `wait_gateway_arp` /
`wait_ping_reply`, so the prediction was **overtaken by a fix** rather
than simply wrong. T4.2 KVM-pod magnitudes are ladder-ordering only, not
report numbers.

Severity legend: **blocker** (would corrupt the baseline or a gate
verdict), **should-fix-before-baseline**, **note-for-report**, **note**,
**cosmetic**. Line numbers are as of `4660fab`.

Disposition (per T4.0 sign-off): findings 31, 9, 12/13, 36 → T4.0b;
finding 3's decomposition → T4.2 verbatim; findings 24/25/26/27/28/30 →
co-edit checklists in D-0057/D-0059/D-0060/D-0061; finding 14 → measured
in T4.1, then decided; findings 16–23 → the report's
numbers-that-must-be-regenerated appendix; findings 33–35, 37–39 (and 36
beyond its const-assert) → T4.3b audit cleanup after the baseline freeze.
Finding 12's *mechanism* was removed in T4.0b; T4.2 measured the
refutation (overtaken-by-fix, not a wrong story about `wfi`).

## 1. Phase stamps — what each delta actually contains

1. **[note]** `START` is honest. `rdtime` into `s2` is the first kernel
   instruction; stored after the `.bss` loop so the store survives zeroing
   (`src/main.rs:60,79-80`). The `.bss`-zero cost lands in the next delta.
2. **[note]** `STVEC` delta = DBCN probe ecall + CSR snapshot reads +
   `trap::install` readbacks (`src/main.rs:111-130`, `src/trap.rs:103-126`).
   Name matches dominant work. µs class.
3. **[should-fix-before-baseline]** `PAGING` (~29 ms) is a four-way
   composite, not "paging". Between STVEC and the stamp at
   `src/page.rs:816` sit: `frame::check_dtb`; **`frame::init` — ~31k
   list-build stores striding ~125 MiB** (`src/frame.rs:85-93`);
   `task::check_layout` + `task::init` (`src/main.rs:171-172`);
   `page::build` — ~32.6k `map()` walks (`src/page.rs:187-196`);
   **`verify()` — a second full pass, `assert_range` walks every mapped
   page** (`src/page.rs:672-691`); then `activate`. Frame-allocator init
   and the verify pass are unlabeled inside "paging"; rung attribution is
   impossible until this is stamped apart.
4. **[note]** `DRIVER_OK` delta hides a doubled program+verify.
   `virtq::init` programs the six queue-address registers and runs full
   `verify()` (`src/virtq.rs:566-568`), then `net::init`'s reset wipes
   those registers (`src/net.rs:261`) and programs+verifies again
   (`src/net.rs:310-311`). Deliberate T3.2/T3.3 layering, but the measured
   delta contains two verifies and two programming passes.
5. **[note]** `FIRST_RX` is "gateway ARP reply arrived". Stamped in
   `classify_rx` (`src/net.rs:496`); the first RX on a standalone boot is
   slirp's ARP reply inside `wait_gateway_arp`. The delta prices ARP RTT
   plus finding 12's tick quantization — not generic RX readiness.
   (Quantization removed by D-0056.3 before T4.2 measured.)
6. **[should-fix-before-baseline]** `LISTEN` misnames its work twice.
   (a) The stamp (`src/net.rs:359`) fires after `wait_gateway_arp` + GARP
   + `ping_gateway` — the delta is mostly a diagnostic ICMP round trip,
   not listen setup. (b) TCP is in `Listen` state from `.bss` zero
   (`src/tcp.rs:80-104`) and SYNs are already served during the ping wait
   (`poll_rx` → `classify_tcp` once the cache holds the gateway,
   `src/net.rs:592-600`) — the machine can serve *before* the LISTEN
   stamp. It is "net-init tail done", not "listen begins".
7. **[should-fix-before-baseline]** `FREEZE` (~6.3 ms) is the accounting
   walk. LISTEN→FREEZE contains `heap::init` (trivial,
   `src/heap.rs:295-312`) plus `task::enter`'s frames-consumed block
   calling `free_count()` — ~31k dependent loads, one per 4 KiB frame
   (`src/task.rs:577-593`, `src/frame.rs:105-117`). `frame::freeze()`
   itself is one bool store; its own `free_count()` println argument is
   not evaluated under fast-boot (`src/console.rs:41-48`), so the whole
   delta is the unlabeled assert.
8. **[note]** `SRET` delta is honest — TCB fetch and state flip, ns class
   (`src/task.rs:596-605`).
9. **[should-fix-before-baseline]** `E3G` is stamped after the doorbell,
   not at publish. Sequence in `tx_tcp_seg`: `post_tx` (the publish,
   `src/net.rs:731`) → `virtq::notify` (`:735`) → stamp (`:738`). Under
   TCG the QueueNotify store runs the device model synchronously in the
   vCPU thread, so E3g lands *after* the frame reached slirp/pcap. D-0043
   and PLAN define E3g as "rdtime at response-TX publish" and promise
   E3w−E3g prices "virtio+slirp transit" — with this placement that
   decomposition is distorted, possibly to ~0 or negative. The SRET→E3G
   delta also bundles the app's `HTTP READY` write, the recv-spin, and
   client SYN arrival (external) with kernel serve time — needs a
   SYN-arrival stamp to separate.

## 2. Measured path (`_start` → E3g, release+fast-boot) — work not structurally necessary to serve the byte

10. **[note]** Costed inventory, pre-registered for T4.2 attribution:
    - `sbi::require_dbcn` probe ecall — µs (`src/main.rs:111`).
    - CSR snapshot reads + `satp != 0` check — sub-µs; loads remain though
      prints are gone (`src/main.rs:113-128`).
    - `timer::init` probe + arm, then a 10 ms tick trap every 10 ms of
      boot (~4 traps × full save/restore + `set_timer` ecall) — tens of µs
      (`src/main.rs:131`, `src/timer.rs:32-49`). Preemption serves nothing
      pre-`sret` in a single-task image — but see finding 13.
    - `frame::init` free-list build — **ms class** (`src/frame.rs:85-93`).
      Structurally necessary only because `page::build` allocates ~67
      frames; a bump high-water mark is O(1).
    - `task::init` fabricates 4 frames, 3 immediately `Exited` — µs
      (`src/task.rs:496-509`).
    - `page::verify()` full second walk — **ms class**; deliberate
      paranoia (D-0043) but unmeasured as its own line
      (`src/page.rs:579-691`).
    - `virtq::init` first program+verify pass, wiped by reset — tens of µs
      (`src/virtq.rs:547-570`).
    - frames-consumed accounting `free_count()` walk — **~6 ms**;
      paranoia, ~free if counted incrementally (`src/task.rs:579`).
    - `print_hex`/format loops still execute with no-op `print!` bodies on
      every RX ARP frame and the GARP (`src/net.rs:522,1060-1078`) —
      sub-µs each.
    - GARP TX + `wait_tx` — tens of µs; politeness, deferrable past E3g in
      principle (`src/net.rs:355,364-377`).
    - `ping_gateway` + `wait_ping_reply` — **ms class**: full ICMP RTT
      plus finding 12's quantization (removed by D-0056.3 before T4.2);
      pure diagnostics (`src/net.rs:356,931-990`).
    - App `HTTP READY` write = 11 DBCN ecalls between SRET and E3g — tens
      of µs; exists only for the non-early-client harness mode
      (`app/src/lib.rs:46`, `scripts/boot-test.sh:97-105`).
    - `USER_OK`/`SYSCALL_OK` one-shot bookkeeping per syscall — ns
      (`src/syscall.rs:73-87`).
    **T4.2 note:** the three wrong-class predictions (`task_init`,
    `virtq_init`, `stvec`) were all µs on paper and sub-ms on the stamp
    table — a systematic bias in these cost estimates, not three
    independent misses. An observation about pre-registration itself.
11. **[note-for-report]** The kernel heap is dead weight in every M3
    production image. Only `heap::self_test` and `stress` ever allocate
    (no `Box`/`Vec`/`String`/`alloc::` outside `heap.rs`/`stress.rs`); the
    1 MiB carve-out and `GlobalAlloc` are M1 apparatus. `heap::init` costs
    ~ns, but the memory-footprint exhibit should state the heap is idle by
    construction.
12. **[should-fix-before-baseline]** `wfi` in the RX wait loops quantizes
    boot latency to the 10 ms tick. `wait_gateway_arp` and
    `wait_ping_reply` sleep on `wfi` (`src/net.rs:433,988`); no NIC
    interrupt can wake it (PLIC unmapped, D-0040), so the only wake source
    is the timer. A reply arriving between ticks waits for the next tick —
    up to 10 ms of hidden, run-to-run-variant dead time per loop.
    Prediction: N-trial IQR on the affected deltas is tick-cadence wide;
    this alone can fail the T4.1 stability criterion.
    **T4.2 disposition: refuted, overtaken by a fix.** Mechanism at
    `4660fab` was real. D-0056.3 already converted those waits to spins,
    so T4.2's release+fast-boot boot measured `first_rx` 0.60 ms with no
    tick quantization — the prediction did not get a fair test against
    the code it described. Report both: the pre-registered claim, and
    that a pre-baseline correction retired it.
13. **[note]** Corollary: boot ticks are load-bearing by accident. If a
    future rung removes timer arming from fast-boot, the first `wfi` in
    `wait_gateway_arp` with nothing pending halts forever — the 2 s
    timeout check is *after* the `wfi`. Any tick-removal rung must first
    convert these waits to spinning.
14. **[should-fix-before-baseline]** The measured build carries
    `-C force-frame-pointers=yes`. `.cargo/config.toml:12` applies to
    release+fast-boot too — a GDB convenience inside the flagship
    configuration. Either measure its delta once and strip it, or record
    it as a stated condition; silently carrying it is neither.
15. **[note]** pcap capture (`-object filter-dump`) is on for every
    measured run (`justfile:11`, `scripts/boot-test.sh:25`,
    `.cargo/config.toml:16`). Fine as standing infra, but "identical
    conditions" requires the Linux/Unikraft invocations to carry it too,
    or timing lanes to drop it symmetrically.

## 5. Whole-tree read — disagreements, dead paths, accidental invariants, surprises

31. **[blocker]** `scripts/boot-test.sh` is fail-open on build failure.
    `set -u` only (line 14); `set -e` first appears at line 135. A failed
    `cargo build` (line 39) does not stop the script — it check-utexts,
    boots, and can print `TEST PASS` on the *previous* stale kernel. Same
    class as the T3.4 hole DEBUGGING.md §4 item 8 documents, sitting in
    the harness every gate runs through. For M4 this is the "before isn't
    real" failure mode in person.
32. **[should-fix-before-baseline]** The CLIENT_EARLY client cannot
    deliver its promised cadence. The loop (`scripts/boot-test.sh:84-96`)
    forks curl per attempt with `--connect-timeout 0.05` + `sleep 0.001`;
    real cadence is dominated by fork/exec (multi-ms), so E4 and
    boot-to-ready carry ~5–15 ms quantization — not the ~1 ms jitter
    D-0043's framing suggests. (Retired by the T4.1 client.)
33. **[note]** `SWITCH_12`/`SWITCH_21` are write-only. `record_switch`
    increments them; nothing reads them since the M2 `sched switches`
    print was retired in M3 (`src/task.rs:620-646`). Dead state kept alive
    by the exact `#[allow(dead_code)]` pattern the M2 policy removed —
    grandfathered, not new.
34. **[note]** Kernel `SEND_FIN` is documentation-only; the implementation
    uses a literal. `net::tcp_send` tests `flags & 1 != 0`
    (`src/net.rs:804`) while `src/syscall.rs:44-46` defines an
    allow(dead_code)'d `SEND_FIN` and `usys/src/lib.rs:33` defines its
    own. Three sites, one literal; a renumber changes wire behavior
    without touching either named const. Related: the allow on
    `ERR_INVALID_PARAM` (`src/syscall.rs:34-36`) is redundant — it is used
    at `:283`.
35. **[note]** `app::abort()` is unreachable-but-compiled in every image
    (`app/src/lib.rs:137-141`) — public, never referenced; the app's
    failure paths all go through `usys::exit` directly.
36. **[note]** `recv` truncation discards data; safety is numeric
    coincidence. `recv_copy` copies `min(payload, ncap)` then consumes the
    *entire* pending payload (`src/syscall.rs:246-253`). TCP is safe only
    because app `BUF` (512, `app/src/lib.rs:37`) == `PAYLOAD_MAX` (512,
    `src/tcp.rs:30`); UDP is not — `UDP_PAYLOAD_MAX` 1472 vs app `BUF` 32
    (`app/src/lib.rs:24`) means any datagram > 32 B echoes truncated. The
    gate payload is 17 B, so it never fires. Invariant by accident, not
    construction.
37. **[cosmetic]** D-0040's wording "NIC touched only from syscall context
    (never from the trap path)" contradicts the mechanism — `sys_recv` →
    `net::poll` executes inside `trap_handler` (an ecall *is* a trap). The
    enforceable invariant is "never from the interrupt path, and no
    allocation in trap context", which the code honors.
38. **[cosmetic]** `src/stress.rs:106-112` prints `heap_bytes={}` but
    passes `heap::region_size()` — the label suggests live free bytes; the
    value is the constant region size (the real check is
    `assert_restored`).
39. **[note]** `src/csr.rs:32` carries a module-wide
    `#![allow(dead_code)]` — every unused accessor the macro generates is
    invisible to the zero-warnings regime forever. Pre-existing; the
    largest remaining blind spot in "zero warnings means no dead code".
40. **[note]** Surprise, positive: `assert-pcap-slirp-arp.sh` /
    `assert-pcap-arp-reply.sh` are invoked by no gate — exactly as
    D-0046's amendment says (kept only for `check-assert-fail-closed.sh`
    coverage); doc and tree agree. Likewise `net-http-selftest` being a
    no-op tag is documented in `Cargo.toml:34-36`. No action.
